# Bootstrap secret generation

The credentials infrastructure needs before Infisical exists, generated by the
hub-operator in Phase 1 of `HubEnvironment` reconciliation.

Everything here is Secret Zero: a credential that cannot come out of Infisical,
because it is part of what lets Infisical start. Every application credential is
delivered by ExternalSecrets instead, and the operator blocks on those arriving
before it provisions a role (`requiredSecrets`, derived from the declared roles).

## `GenerateBootstrapSecrets`

Idempotent, and that matters more here than anywhere else: a regenerated password
re-keys a database or an encrypted store out from under itself, so an existing
value is always reused.

| Secret | Namespace | What it is |
|---|---|---|
| `infisical-db-credentials` | `platform-data` | `username: infisical` and its password, basic-auth. CloudNativePG's `bootstrap.initdb.secret` on `infisical-db` reads it, so the owner role and the database come from it |
| `infisical-secrets` | `platform-security` | `ENCRYPTION_KEY`, `AUTH_SECRET`, `REDIS_URL`, `DB_ROOT_CERT` |
| `infisical-redis-credentials` | `platform-data` | the same Redis password, for Redis |
| `infisical-postgres-connection` | `platform-security` | the connection Infisical's pods mount, addressed at `Spec.Database.ClusterRef`'s read-write service with `sslmode=require` |

`DB_ROOT_CERT` comes from `infisical-db-ca`, which CloudNativePG creates with the
cluster — not from a CA this package generates. Certificate authorities are
cert-manager's (ADR-035). When the Secret is not there yet the field is left empty
and filled on a later reconcile, because the cluster legitimately does not exist
on the first pass.

Every Secret carries an `ownerReference` to the `HubEnvironment`, so they are
garbage collected with it, and credential Secrets carry
`ops.nutgraf.in/db-credentials=true`.

## Helpers

- `GenerateSecurePassword` — 32 hex characters from `crypto/rand`
- `GenerateSecurePasswordWithCharset` — the same, where a store restricts the alphabet
- `GenerateHexKey` — an n-byte key, hex encoded
- `GenerateEd25519KeyPair` — a signing key, PEM private and base64 public

## Usage

```go
result, err := secrets.GenerateBootstrapSecrets(ctx,
    dataNamespace, securityNamespace, dbHost, owner,
    existingSecrets, isFirstTime, escrowID, escrowClient)
```

`dbHost` is derived from the CR, never spelled here: `database.Endpoint{Cluster:
hubEnv.Spec.Database.ClusterRef, Namespace: ...}.PrimaryHost()`. A literal would
address one application's cluster on behalf of another (ADR-112).
